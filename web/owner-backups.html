Backups

Every night the site makes a copy of all its data, locks it with a key, and puts it in storage that you own, away from this server. If the server is ever lost, that copy and your key bring everything back.

Where backups are kept

Backups go to a private storage bucket that you rent from a storage company. It must be a different company from the one that runs this server, so one accident cannot take both. Most storage companies work, as long as they offer "S3-compatible" storage.

How to make a bucket and its key

With any storage company the job is the same four things, all done on their website:

  1. Make a new bucket. Keep it private (not public).
  2. Make an access key that can read and write that one bucket only. You get two values: a key id and a secret. The secret is shown once.
  3. Find the storage address. Companies call it the "S3 endpoint" or "S3 API address". It starts with https://
  4. Paste the four values into the form below.

Worked example: Cloudflare R2

  1. Log in at dash.cloudflare.com and open R2 Object Storage in the menu on the left. The first time, Cloudflare asks you to add a payment card to turn R2 on.
  2. Press Create bucket. Give it a name such as maiz-backups, leave the other choices as they are, and press Create bucket.
  3. Go back to the R2 overview and press Manage API tokens, then Create API token.
  4. Under Permissions choose Object Read & Write. Under "Specify bucket" choose Apply to specific buckets only and pick your bucket. Press Create API token.
  5. Cloudflare now shows an Access Key ID, a Secret Access Key and, under "Use jurisdiction-specific endpoints for S3 clients", an address ending in .r2.cloudflarestorage.com. Copy all three before you leave the page.
  6. Paste them below. Leave Region empty.

Cloudflare changes the names of its buttons from time to time. If a name here does not match, look for the nearest one. Check your storage company's price list yourself: this page does not know what they charge.

Before saving, the site writes a small test file to your bucket, finds it again and removes it. If any of that fails, nothing is saved and you are told why.

Turn backups off? The nightly backup stops. Backups already in your storage stay there, and your recovery key is kept so they can still be opened.

Your recovery key

Every backup is locked with a recovery key. Without the key a backup is unreadable, to a thief and to you. The site makes the key and shows it to you once.

The honest part.The server keeps its own copy of the key, encrypted, so it can make the nightly backup and test it without you. That copy lives on this server. If the server is lost, its copy is lost with it, and the copy you saved is the only way to open a backup. Nobody at MAIZ can make the key again or show it a second time.

If the server is ever lost

You need two things: a backup file from your storage, and your recovery key. Give both to the person who rebuilds the server. Each backup also carries the server's own lock for saved passwords and tokens, sealed with your recovery key, so the one key brings everything back.

The exact steps for that person are in the file docs/BACKUPS.md in the code, under "Restoring for real". They need the code and the key. They do not need the old server.
